- **Como se organizan la CPU, el modulo (de E/S) y la memoria para mover los datos? Hay tres estrategias fundamentales:

1. **E/S Programada y Espera de Respuesta (Espera Ociosa)**
	- **Funcionamiento:** La CPU tiene el control absoluto y directo de la operacion. Realiza todo el trabajo de forma manual.
	- **El flujo fisico en bucle:**
		1. La CPU lee el registro de estado del modulo para ver si el periferico esta listo.
		2. Si el bit de estado dice "no listo", **la CPU vuelve a leer el registro en un bucle (espera ociosa)**.
		3. Cuando finalmente esta listo, la CPU lee o escribe un unico dato.
		4. Si hay mas datos, vuelve al paso 1.
	- **Desventaja:** Desperdicio total de procesamiento. La CPU se queda congelada esperando a que el lento periferico responda.

2. **E/S Programada mediante interrupciones**
	- **Funcionamiento:** Para evitar la espera ociosa, la CPU inicia la transferencia y **sigue haciendo trabajo util**.
	- **El flujo fisico:** Cuando el modulo de E/S tiene el dato listo (o termino de escribir), le envia un pedido de interrupcion a la CPU. La CPU termina su instruccion actual, salva su estado (PC y PSW) en la pila y salta a ejecutar la rutina de transferencia de ese dato. Al terminar, recupera el estado y sigue con su programa.
	- **Como sabe la CPU quien interrumpio? (Estrategias de identificacion):**
		- *Multiples lineas:* Una linea fisica por dispositivo (dificil de escalar porque la CPU tiene pocas lineas).
		- *Consulta Software (Polling)*: Una sola linea comun. Cuando se activa, la CPU ejecuta una rutina que le pregunta uno por uno a los dispositivos: "Fuiste vos?" (Es sumamente lento).
		- *Conexion en cadena:* Comparten linea de interrupcion. La señal de confirmacion de la CPU viaja encadenada de modulo en modulo. El primer modulo listo en la cadena interrumpe la señal y coloca su vector de identificacion en el bus.
		- *Arbitraje de bus (Vectorizada):* Una sola linea INTR. Un chip dedicado (**EL PIC**) se encarga de priorizar y poner en el bus el vector del dispositivo demandante.

3. **Acceso Directo a Memoria (DMA)**
	- **Funcionamiento:** Mueve bloques masivos de datos entre el periferico y la memoria principal **sin que intervenga la CPU** para cada dato. Es controlado por un chip dedicado llamado DMAC (Controlador de DMA), que es capaz de "imitar" a la CPU y tomar el control de los buses del sistema (*Bus Master*.)
	- **Las 3 Fases del DMA:**
		1. **Fase de Inicializacion:** La CPU configura el periferico y el DMAC. Al DMAC le indica: la cantidad de palabras a transferir (registro de cuenta de datos), el tipo de transferencia (lectura/escritura) y la direccion de memoria de inicio (registro de direcciones).
		2. **Fase de Ejecucion:** Cuando el periferico esta listo, le pide al DMAC iniciar. El DMAC le solicita el control del bus a la CPU. La CPU suelta el bus, le avisa al DMAC mediante una señal de control y se desentiende. El DMAC toma el control, le avisa al periferico y transfiere los datos uno por uno directo a la RAM, actualizando automaticamente sus registros internos de direccion y cuenta.
		3. **Fase de Finalizacion:** Al terminar de transferir todo el bloque, el DMAC libera el bus y le envia una interrupcion a la CPU. La CPU retoma el bus y verifica en los registros del DMAC que todo haya salido bien.
	- **Tecnicas de transferencia de bus en DMA:**
		- **Por Rafaga (Burst):** El DMAC toma el bus y **no lo suelta** hasta transferir el bloque de datos completo. La CPU no puede usar el bus durante ese tiempo.
		- **Por Robo de Ciclo (Cycle-stealing):** El DMAC toma el bus, transfiere un solo dato y le devuelve el bus a la CPU para que ejecute una instruccion. Repite esto secuencialmente. *Dato clave:* No requiere salvar contexto.

4. **Canales de E/S**
	- **Funcionamiento:** Son una evolucion directo del DMA. Es un procesador independiente con su propia memoria y repertorio de instrucciones dedicado a la E/S. El programa que ejecuta el canal esta guardado en la memoria principal. La CPU solo le dice al canal: "Ejecuta este programa de E/S que esta en tal direccion de la RAM" y el canal hace todo el control de forma autonoma.
	- **Tipos de Canales:**
		- **Canal Selector:** Controla perifericos rapidos de a uno por vez (se dedica exclusivamente a un dispositivo durante su transferencia).
		- **Canal Multiplexor:** Controla multiples perifericos simultaneamente. Puede ser:
			- *Multiplexor de byte:* Para dispositivos lentos; va entrelanzando bytes de distintos dispositivos.
			- *Multiplexor de bloque:* Para dispositivos rapidos; va entrelazando bloques completos de datos.
